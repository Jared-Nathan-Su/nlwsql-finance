# 需求分析文档 — 企业财务智能问数与经营分析系统

## 一、项目概述

### 1.1 项目名称
**NL2SQL财务智能问数助手** — 基于大模型的企业财务智能问数与经营分析系统

### 1.2 项目定位
面向企业管理层、财务总监、部门经理等非技术用户，提供自然语言驱动的财务报表自助查询与AI经营分析服务。

### 1.3 赛道方向
**经营分析** — AI驱动的多维度经营指标异常检测、自然语言问数（NL2SQL/对话式分析）、管理层经营简报AI自动生成

---

## 二、业务背景与痛点分析

### 2.1 现状描述
- 企业管理层需要频繁查看经营数据（收入、成本、毛利、费用、应收应付等）
- 传统流程：管理层提问题 → BI分析师理解需求 → 编写SQL → 出报表 → 反馈结果
- 整个链路涉及多轮沟通，平均耗时 **1-3天**

### 2.2 核心痛点

| 痛点 | 具体表现 | 影响 |
|------|----------|------|
| **响应慢** | 问数从天级起步，无法支撑快速决策 | 错失市场机会 |
| **门槛高** | 非技术人员无法自助查数据，必须依赖BI团队 | BI团队成为瓶颈 |
| **沟通损耗** | 业务语言→技术语言翻译过程容易出错 | 查出来的不是想要的 |
| **分析浅** | 只给数据不给解读，管理层仍需自己分析 | 决策效率低 |
| **不主动** | 异常指标靠人发现，容易遗漏 | 风险发现滞后 |

### 2.3 目标用户画像

| 用户角色 | 典型需求 | 使用频率 |
|----------|----------|----------|
| CEO/总经理 | 全局经营概览、核心KPI趋势 | 每日/每周 |
| 财务总监 | 利润分析、费用管控、现金流 | 每日 |
| 销售总监 | 区域/产品线/客户维度收入分析 | 每周 |
| 部门经理 | 本部门预算执行、费用明细 | 每周/每月 |

## 三、功能需求

### 3.1 核心功能：自然语言问数（NL2SQL）

**功能描述：** 用户输入自然语言问题，系统自动转换为SQL并执行查询

**典型问数场景（20个）：**

| 编号 | 问题类型 | 示例问题 |
|------|----------|----------|
| Q1 | 简单查询 | "今年Q2的总营收是多少？" |
| Q2 | 多维过滤 | "华东区2024年每个月的销售收入" |
| Q3 | 聚合计算 | "各产品线的年度毛利率排名" |
| Q4 | 同比分析 | "Q2毛利率同比变化了多少？" |
| Q5 | 环比分析 | "本月费用环比上个月增长了多少？" |
| Q6 | 排序TopN | "应收账款余额最高的5个客户" |
| Q7 | 条件筛选 | "毛利率低于20%的产品线有哪些？" |
| Q8 | 趋势分析 | "近三年各季度营收变化趋势" |
| Q9 | 预算对比 | "哪些部门预算执行率低于80%？" |
| Q10 | 异常检测 | "费用率连续3个月上升的部门" |
| Q11 | 多维交叉 | "华南区各产品线Q3的毛利和毛利率" |
| Q12 | 占比分析 | "各区域营收占总营收的比例" |
| Q13 | 客户分析 | "本年新增客户的贡献收入占比" |
| Q14 | 回款分析 | "逾期超过30天的应收账款有哪些？" |
| Q15 | 现金流 | "预测本月现金流能否覆盖应付账款？" |
| Q16 | 费用结构 | "销售费用中占比最大的三项是什么？" |
| Q17 | 利润拆解 | "净利润下降的主要原因是什么？" |
| Q18 | 对比分析 | "对比今年和去年同期的费用结构" |
| Q19 | 排名变化 | "毛利率排名下降超过3名的产品线" |
| Q20 | 综合经营 | "给我一份本月经营简报" |

### 3.2 辅助功能：AI经营分析解读

- 查询结果自动解读（1-2句核心摘要）
- 异常指标自动标注与原因推测
- 经营风险提示与行动建议

### 3.3 辅助功能：可视化图表

- 自动选择合适的图表类型（柱状图/折线图/饼图）
- 支持趋势图、对比图、构成图

## 四、非功能需求

| 指标 | 目标值 |
|------|--------|
| SQL生成准确率 | > 85% |
| 端到端响应时间 | < 10秒 |
| 支持的并发用户 | 5-10人 |
| 数据规模 | 10万+行，3年数据 |
| 系统可用性 | 7×24小时 |

## 五、技术约束

- 使用 Python 技术栈
- 大模型API：支持 DeepSeek / 通义千问 / OpenAI 等可替换
- 数据库：SQLite（本地开发）/ MySQL（生产）
- 前端：Streamlit（快速原型）
- 所有代码需可本地运行，不依赖企业内部系统
