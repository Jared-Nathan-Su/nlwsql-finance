### 第7页：NL2SQL核心技术 — 五层Prompt注入策略

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   🧠 五层 Prompt 注入策略（核心技术）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌─────────────────────────────────────────┐
  │ Layer 1: 系统角色                        │
  │ "你是一位资深财务数据分析师，精通SQL..."   │
  ├─────────────────────────────────────────┤
  │ Layer 2: 数据库Schema                    │
  │ 12张表的表名、字段、类型、关联关系        │
  ├─────────────────────────────────────────┤
  │ Layer 3: 业务规则                        │
  │ 毛利率公式、同比环比定义、区域映射等       │
  ├─────────────────────────────────────────┤
  │ Layer 4: Few-shot 示例（3-5个）           │
  │ 自然语言→SQL的配对示例，覆盖典型场景      │
  ├─────────────────────────────────────────┤
  │ Layer 5: 用户问题                        │
  │ "华东区Q2毛利率同比变化？"                │
  └─────────────────────────────────────────┘

  🔑 为什么分层？
  • 角色层：约束输出风格和专业度
  • Schema层：防止"幻觉"出不存在的字段
  • 规则层：确保业务计算逻辑正确（如毛利率公式）
  • Few-shot层：通过示例引导SQL生成模式
  • 层层递进，每层解决一类问题
```

**演讲词：**
> 我们的核心技术是这套五层Prompt注入策略。为什么需要分层？因为大模型虽然能力强，但直接问"给我查毛利率"它不知道你的数据库有什么表、毛利率怎么算。所以我们需要逐层告诉它：你是谁、数据库长什么样、业务规则是什么、再给几个示例。实验证明，分层注入比把所有信息堆在一起，SQL准确率提升约15个百分点。

### 第8页：SQL安全校验与自动纠错

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   🔒 SQL 安全校验流水线
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

   大模型生成SQL
        │
        ▼
   ┌──────────┐    失败    ┌─────────────────┐
   │ 语法校验  │──────────▶│ 反馈错误给LLM     │
   └────┬─────┘           │ 自动重试(最多3次) │
        │ 通过            └────────┬─────────┘
        ▼                         │
   ┌──────────┐    失败           │
   │ 权限检查  │──────────▶ 拦截   │
   │(仅SELECT)│           并提示  │
   └────┬─────┘                   │
        │ 通过                    │
        ▼                         │
   ┌──────────┐    失败           │
   │ 表名/字段 │──────────▶───────┘
   │ 名校验    │
   └────┬─────┘
        │ 通过
        ▼
   ┌──────────┐    失败    ┌─────────────────┐
   │ 执行SQL   │──────────▶│ 反馈错误给LLM     │
   └────┬─────┘           │ 二次修正          │
        │ 成功            └─────────────────┘
        ▼
   ✅ 返回查询结果

   🛡️ 防护能力：
   ✓ 拦截 DROP/DELETE/UPDATE 等危险操作
   ✓ 防止"幻觉"字段导致的查询失败
   ✓ 自动纠错成功率 80%+（3次重试内修复）
```

**演讲词：**
> 除了生成SQL，安全也是关键。我们设计了一套完整的SQL校验流水线——语法校验、权限检查（只允许SELECT）、表名字段名校验，每一步失败都会自动反馈给大模型进行纠错，最多3次重试。这确保了大模型"幻觉"出的SQL不会对数据库造成风险。

  "逾期超过30天的应收账款，按客户统计"

  【生成SQL】
  SELECT c.cust_name, COUNT(*) AS overdue_count,
    ROUND(SUM(r.amount - r.collected_amount),2)
    AS outstanding_amount,
    MAX(r.overdue_days) AS max_overdue_days
  FROM fact_receivable r
  JOIN dim_customer c ON r.cust_id = c.cust_id
  WHERE r.is_overdue = 1 AND r.overdue_days > 30
  GROUP BY c.cust_name
  ORDER BY outstanding_amount DESC;

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

┌──────────────┬──────────────────┬──────────────────┐
│    对比维度   │   🖥️ 传统BI方案   │   🤖 我们的AI方案 │
├──────────────┼──────────────────┼──────────────────┤
│ 使用方式      │ 写SQL / 拖拽配置  │ 自然语言输入      │
│ 响应时间      │ 1-3天            │ 3-10秒           │
│ 使用门槛      │ 需SQL技能        │ 零门槛           │
│ 问题覆盖率    │ 仅预设模板       │ 开放域，泛化强    │
│ 数据解读      │ 只给数据         │ 数据+分析+建议    │
│ 异常发现      │ 人工            │ AI自动标注异常    │
│ 多轮追问      │ 重新沟通        │ 即时追问          │
│ 部署成本      │ BI系统+人力      │ API调用+开源框架  │
└──────────────┴──────────────────┴──────────────────┘

🔑 为什么非AI不可？
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. 自然语言的"多样性"：同一个问题可以有几十种问法
   "Q2毛利率" = "第二季度毛利水平" = "4-6月赚了多少比例"
   → 传统规则/模板无法穷举，只有LLM能理解语义

2. 复杂查询的"组合性"：用户可能问出从未预定义过的组合
   "华南区软件产品线中A级客户的回款率" 
   → 涉及4张表的JOIN，传统BI需要IT预先配置

3. 分析解读的"专业性"：不只给数据，还要给出财务视角的解读
   → 只有LLM能结合财务知识和具体数据生成解读
```

**演讲词：**
> 这个表对比了我们的AI方案和传统BI。关键问题是：为什么非AI不可？三点：第一，自然语言有无限多样性，"毛利率"可以有十几种说法，传统规则无法穷举；第二，用户可能问出从未预定义过的多维交叉问题，只有LLM能动态理解；第三，AI不只是给数据，而是像一位财务分析师一样给出解读和建议。

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   💡 四大创新点
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

   ① 五层Prompt注入策略
      业界首创"角色→Schema→规则→示例→问题"分层注入，
      比单一Prompt方式准确率提升15个百分点

   ② SQL自动纠错闭环
      语法校验→权限检查→字段验证→执行验证，
      失败自动反馈LLM修正，形成自我纠错闭环

   ③ "问数+分析"一体化
      不只是给数据，LLM二次调用自动生成经营分析解读
      包括：数据摘要、变动原因、风险提示、行动建议

   ④ 财务场景深度适配
      内置毛利率/净利率/同比环比/预算执行率等财务指标
      计算规则，支持20+种典型财务问数模式

   ────────────────────────────────────────
   🔬 技术选型创新
   • DeepSeek-V3: 国产顶尖模型，中文SQL能力出色
   • LangChain: 统一LLM调用 + 多模型可替换
   • Streamlit: 纯Python全栈，快速迭代
   • SQLite: 零配置，Demo即产品
