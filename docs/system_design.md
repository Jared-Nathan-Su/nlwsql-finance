### 2.2 表结构详细说明

#### 维度表

**dim_date** — 日期维度（1096行，约3年）
| 字段 | 类型 | 说明 |
|------|------|------|
| date_id | INTEGER PK | 日期ID (YYYYMMDD) |
| full_date | DATE | 完整日期 |
| year | INTEGER | 年份 |
| quarter | INTEGER | 季度 (1-4) |
| month | INTEGER | 月份 (1-12) |
| month_name | TEXT | 月份名称 |
| day_of_month | INTEGER | 日 (1-31) |
| day_of_week | INTEGER | 星期几 (0-6) |
| is_weekend | INTEGER | 是否周末 (0/1) |

**dim_product** — 产品维度（12个产品）
| 字段 | 类型 | 说明 |
|------|------|------|
| product_id | INTEGER PK | 产品ID |
| product_name | TEXT | 产品名称 |
| category | TEXT | 产品品类（硬件/软件/服务） |
| product_line | TEXT | 产品线 |

**dim_department** — 部门维度（8个部门）
| 字段 | 类型 | 说明 |
|------|------|------|
| dept_id | INTEGER PK | 部门ID |
| dept_name | TEXT | 部门名称 |
| dept_type | TEXT | 部门类型（前台/中台/后台） |

**dim_region** — 区域维度（6个区域）
| 字段 | 类型 | 说明 |
|------|------|------|
| region_id | INTEGER PK | 区域ID |
| region_name | TEXT | 区域名称 |
| region_group | TEXT | 大区（华东/华南/华北/华中/西南/西北） |

**dim_customer** — 客户维度（50个客户）
**dim_supplier** — 供应商维度（20个供应商）
**dim_expense_type** — 费用类型维度（10类）

#### 事实表

**fact_sales** — 销售事实表（约36000行）
| 字段 | 类型 | 说明 |
|------|------|------|
| sale_id | INTEGER PK | 销售记录ID |
| date_id | INTEGER FK | 日期ID |
| product_id | INTEGER FK | 产品ID |
| region_id | INTEGER FK | 区域ID |
| dept_id | INTEGER FK | 部门ID |
| cust_id | INTEGER FK | 客户ID |
| revenue | REAL | 销售收入（元） |
| quantity | INTEGER | 销售数量 |

**fact_cost** — 成本事实表（约36000行）
**fact_expense** — 费用事实表（约24000行）
**fact_receivable** — 应收账款表（约5000行）
**fact_payable** — 应付账款表（约3000行）

### 2.3 核心业务指标定义

| 指标 | 计算公式 | 对应SQL |
|------|----------|---------|
| 毛利率 | (收入-成本)/收入 × 100% | `(SUM(revenue)-SUM(cost_amount))/SUM(revenue)*100` |
| 净利率 | (收入-成本-费用)/收入 × 100% | 多表JOIN计算 |
| 费用率 | 费用/收入 × 100% | `SUM(actual_amount)/SUM(revenue)*100` |
| 同比(YoY) | (本期-去年同期)/去年同期 × 100% | 自连接+日期偏移 |
| 环比(MoM) | (本月-上月)/上月 × 100% | LAG窗口函数 |
| 预算执行率 | 实际/预算 × 100% | `actual_amount/budget_amount*100` |
| 应收周转天数 | 平均应收/日均收入 | 聚合计算 |
| 回款率 | 已收/应收 × 100% | `collected_amt/amount*100` |

## 三、NL2SQL 引擎设计

### 3.1 Prompt 工程架构

采用**分层注入**策略，共5层：

```
┌──────────────────────────────────────┐
│ Layer 1: System Role（系统角色）      │
│ "你是一位资深财务数据分析师，精通SQL" │
├──────────────────────────────────────┤
│ Layer 2: Schema Context（数据库语境） │
│ 所有表名、字段名、字段含义、关联关系  │
├──────────────────────────────────────┤
│ Layer 3: Business Rules（业务规则）   │
│ 毛利率公式、同比环比定义、关联键等    │
├──────────────────────────────────────┤
│ Layer 4: Few-shot Examples（示例）    │
│ 3-5个 自然语言→SQL 配对              │
├──────────────────────────────────────┤
│ Layer 5: User Question（用户问题）    │
│ {用户输入的自然语言}                  │
└──────────────────────────────────────┘
```

### 3.2 SQL 安全校验流水线

```
原始SQL
  │
  ▼
[语法校验] ──失败──▶ [错误反馈给LLM重试]
  │ 通过
  ▼
[权限检查] ──含DML──▶ [拦截+提示用户]
  │ 通过（仅SELECT）
  ▼
[表名校验] ──不存在──▶ [模糊匹配建议]
  │ 通过
  ▼
[字段名校验] ──不存在──▶ [错误反馈给LLM重试]
  │ 通过
  ▼
[执行SQL] ──成功──▶ 返回结果
  │ 失败
  ▼
[错误反馈LLM重试]（最多3次）
```

### 3.3 结果分析 Prompt 设计

```
基于以下查询结果，请用财务分析视角做简要解读：

查询问题：{user_question}
生成SQL：{generated_sql}
查询结果：{query_result}

请按以下格式输出：
1. 📊 核心数据摘要（1-2句话）
2. 🔍 关键发现与原因分析
3. ⚠️ 风险提示（如有异常）
4. 💡 行动建议
```

## 五、安全设计

1. **只读权限**：仅允许 SELECT 语句，拦截所有 DML/DDL
2. **SQL注入防护**：参数化查询，输入过滤
3. **API Key 保护**：通过环境变量或 Streamlit Secrets 管理
4. **查询限流**：单用户每分钟最多 10 次查询
